# Fraud Detection: GraphSAGE + Reinforcement Learning

A demo system that detects money-mule ("smurfing") networks in a transaction graph. A GraphSAGE model turns each account and its neighbourhood into an embedding. A reinforcement-learning agent then decides **Allow**, **Review** or **Block** for every account. Results are written to `live_graph.json` and served by a Flask API to a dashboard.

> **Demo project.** All data is synthetic. No real transactions are used, and the results are not production accuracy figures (see [Limitations](#limitations)).

## How it works

```
generate synthetic graph ──> GraphSAGE embeddings ──> RL agent (Allow / Review / Block)
                                                              │
                                              live_graph.json (every 5 epochs)
                                                              │
                                              Flask API (app.py) ──> dashboard
```

1. **Graph.** `GraphAi.py` builds a graph of 1,000 normal accounts and 50 fraud accounts. The fraud accounts form 5 syndicates of 10 nodes each: one source fans out to 8 mules, and the mules fan in to one destination. Syndicate ends also send money to normal accounts as camouflage. Each node has 15 features.
2. **Embedder.** A 2-layer GraphSAGE (`SAGEConv`, 15 to 32 to 16 dimensions, ReLU, dropout 0.3).
3. **Agent.** A small policy network (16 to 16 to 3, softmax) samples an action per node and is trained with a policy-gradient loss.
4. **Rewards.**

| Account is | Allow | Review | Block |
|---|---|---|---|
| Fraud | -20 | +5 | +15 |
| Normal | +1 | -2 | -25 |

5. **Export.** Every 5 epochs the script writes a subset of nodes and links, plus training statistics, to `live_graph.json`.
6. **API.** `app.py` reads that file and exposes it to the dashboard.

## Quick start

Requirements: Python 3.10+, PyTorch, PyTorch Geometric.

```bash
pip install torch torch_geometric numpy flask flask-cors
```

1. Train and export (runs 5,000 epochs and rewrites `live_graph.json` as it goes):
```bash
   python GraphAi.py
```
2. Start the API in a second terminal:
```bash
   python app.py
```

## API

| Endpoint | Returns |
|---|---|
| `GET /api/stats` | Counters (transactions processed, flagged, pending review, confirmed fraud), epoch and average reward |
| `GET /api/flag_rate` | 24-hour flag-rate series |
| `GET /api/decisions` | Counts of Allow, Review and Block decisions |
| `GET /api/alerts` | Up to 25 alerts with severity, risk score and decision |
| `GET /api/fraud_graph` | Nodes and links for the graph view |

## Limitations

- **Synthetic data.** The graph, features and fraud patterns are generated by the code, so performance on real transactions is unknown.
- **No held-out test set.** The agent is trained and scored on the same graph, so rewards show learning, not generalization.
- **Some dashboard values are simulated.** In `app.py`, batch sizes, the flag-rate chart, alert transaction IDs, amounts and some risk scores are randomized for display. In `GraphAi.py`, the exported node `risk` is drawn from a range based on the true label, not from a model output.
- **Single pattern.** Only one fraud pattern (fan-out and fan-in smurfing) is modeled.
